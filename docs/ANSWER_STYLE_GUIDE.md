# 青云问道结构化口述答案规范

## 1. 目标

每个口述答案都让学生知道三件事：第一句怎么开口、中间按什么路线说、最后怎样收住。

该规范依据高校复试规程中反复出现的评价维度制定：专业知识的广度与深度、知识运用、思维与应变、要点覆盖、层次与逻辑、语言准确简洁。代表性公开依据包括[中国科学院大学数学科学学院推免复试规程](https://math.ucas.edu.cn/index.php/zh-CN/zsjy/sszs/3072-2025-2)、[济南大学推免生复试办法](https://yz.ujn.edu.cn/info/1011/3904.htm)、[首都体育学院专业理论面试评分标准](https://smiic.cupes.edu.cn/rcpy/yjszs/80c686bc7a6e409baacbe47bd7801a11.htm)和[中国地质大学（武汉）专业能力评分标准](https://jgxy.cug.edu.cn/info/1133/12354.htm)。

## 2. 数据结构

在现有 `answer` 中增加可选字段：

```json
{
  "spoken": "保留的完整口述答案",
  "structure": {
    "direct": "先直接回答问题的核心结论。",
    "points": [
      { "title": "定义与本质", "content": "第一个展开要点。" },
      { "title": "机制与过程", "content": "第二个展开要点。" }
    ],
    "summary": "最后用一句话重申核心结论。"
  },
  "explanation": "详细知识解析",
  "memoryHook": "记忆钩子"
}
```

- `direct`：1–2 句，先答问题，不说空泛背景。
- `points`：2–5 个，每点只承担一个逻辑任务；标题优先使用“定义与本质 / 机制与过程 / 比较与区别 / 复杂度与代价 / 场景与应用 / 条件与边界 / 优化与改进 / 例子与理解”。
- `summary`：一句话收束，可与开头形成首尾呼应。
- `explanation`：允许更完整的推导、证明、实现细节和易错点，不要求全部在首答中说完。

## 3. 前端视觉

训练页的口述答案采用“答题路标”而非长段落：

```text
┌ 先答一句 ───────────────────────┐
│ 核心结论（字号稍大）             │
└────────────────────────────────┘
  01  定义与本质   ……
  02  机制与过程   ……
  03  条件与边界   ……
┌ 最后收住 ───────────────────────┐
│ 一句话总结                       │
└────────────────────────────────┘
```

- 编号是真实口述顺序，不是装饰。
- 每点用标题作为回忆提示，用正文作为可说出口的句子。
- 不把每点做成需要点击的折叠项，避免增加训练操作成本。
- 手机端保持单列，编号、标题和正文明确分层。

## 4. 兼容规则

- 新默认题库 246 题必须全部含 `structure`。
- 旧导入题库没有 `structure` 时继续显示 `spoken`，不拒绝导入。
- 搜索同时覆盖 `spoken`、结构化首答、各要点和总结。
- 题目 ID、院校、来源、分类与用户进度键不变。

## 5. 视觉约束与自检

- 色彩沿用纸白、墨色、青玉和少量金色，不新增通用 SaaS 渐变。
- 宋体只用于问题与首答重点，正文要点继续使用易读黑体。
- 唯一强调装置是从 `01` 到 `05` 的纵向口述路线；编号在这里代表真实回答顺序，因此不是装饰。
- 首答、要点、收束之间主要靠留白、细线和字号建立层级，不把每一点做成悬浮卡片。
- 设计自检：如果去掉“先答一句 / 分点展开 / 最后收住”的内容语义，这套组件不能直接套用到普通 Dashboard；因此它与面试口述训练场景绑定，而非通用模板。
