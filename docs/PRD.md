# 青云问道 · Qingyun Viva — 产品需求文档（PRD）

> 产品副标题：保研专业课面试训练台  
> Slogan：**以问促学，以答验知。**  
> 目标仓库：`LiPume/qingyun-viva`  
> 目标部署：GitHub Pages，最终公开入口应为 `https://lipume.github.io/qingyun-viva/`

## 1. 产品背景

现有专业课资料已经形成一套较完整的保研面试题库，但 Word 更适合作为“查阅手册”，不适合每天进行主动回忆、闭卷口述、追问和间隔复习。

青云问道不是把 Word 搬到网页上，而是把专业课复习改造成一个可持续的训练闭环：

**抽题 → 独立口述 → 查看口述答案 → 理解知识点 → 接追问 → 自评 → 自动安排复习 → 全真模拟。**

产品可以参考已有项目 `LiPume/qingyun-speak` 的训练哲学和工程结构，但必须针对专业课面试重做信息架构、数据模型和视觉语言。

## 2. 初始数据资产

默认题库来自：`保研专业课面试_口述版题库_v3_精排导航补全版.docx` 的结构化转换。

首版数据规模：

- 总题目：246 道
- 公共专业课：143 道
  - S 级：56 道
  - A 级：45 道
  - B 级：42 道
- 12 所目标院校定向题：103 道
- 题目总优先级分布：S 133 / A 71 / B 42
- 跨校高频问题：24 个主题
- 内置 28 天复习计划
- 内置排序算法速查表
- 保留“截图真题 / 同校面经 / 官方范围 / 官方方向 / 高概率预测 / 联网补充”等证据标签

首版 12 所目标院校：国防科技大学、同济大学、天津大学、东南大学、上海财经大学、华东师范大学、复旦大学、西安电子科技大学、北京邮电大学、厦门大学、浙江大学、西北工业大学。

## 3. 核心用户与场景

### 3.1 核心用户

保研预推免阶段、需要在数周内强化专业课面试口述能力的计算机 / AI 学生。

### 3.2 典型场景

1. 每天打开网站，不想自己决定今天复习什么。
2. 明明“看答案会”，但老师一问就组织不出来。
3. 想只刷某所学校的高概率题和真题。
4. 第一问会答，但老师继续追问时容易崩。
5. 想知道哪些题从来没正式开口练过，哪些已经长期没复习。
6. 面试前需要 10~20 分钟的全真随机模拟。
7. 想持续补充新的面经 JSON，而不是每次改代码。

## 4. 产品目标

### 4.1 首要目标

让“掌握”从“看懂答案”变成“无资料时可以稳定开口并接住追问”。

### 4.2 成功标准

用户能够：

- 5 秒内开始回答 S 级问题；
- S 级问题连续口述 45~90 秒；
- 至少接住 1 个追问；
- A 级问题 20~40 秒说清定义 / 机制 / 场景；
- 明确区分真题、官方范围、同校经验和预测题；
- 每天只需打开首页即可获得明确训练任务；
- 随时查看薄弱题、到期题和目标院校覆盖率。

## 5. 非目标

首版明确不做：

- 不接入云端账号系统；
- 不做后端数据库；
- 不强依赖任何 LLM / API Key；
- 不做 AI 自动“百分制评分”；
- 不做复杂可视化知识图谱；
- 不把产品做成纯文档阅读器；
- 不在未经证据支持时把预测题显示为真题。

## 6. 信息架构

主导航建议保持 5~6 个一级入口：

1. **今日研习** `/`
2. **题库** `/questions`
3. **院校** `/schools`
4. **模拟面试** `/mock`
5. **复习簿** `/review`
6. **设置** `/settings`

题目详情：`/question/:questionId`

GitHub Pages 使用 `HashRouter`，避免深层路由刷新 404。

## 7. P0 功能需求

### 7.1 今日研习 Dashboard

首页必须解决“今天做什么”。

包含：

- 今日总目标题数；
- 各模块目标：数据结构、计网、OS、计组/编译、数据库、数学、ML、项目追问等；
- 当前选中的“院校模式”；
- 推荐队列；
- 今日完成度；
- 本周连续训练天数；
- S 级覆盖率；
- 到期复习数量；
- 红 / 黄薄弱题数量。

推荐优先级：

1. 到期的红题；
2. 到期的黄题；
3. 从未正式练过的 S 题；
4. 当前院校的真题 / 官方范围题；
5. 久未复习的 S / A 题；
6. 其他扩展题。

首页不允许把“看过答案”计入完成，只有完成自评才算正式练习。

### 7.2 专业课题库

题库必须支持组合筛选：

- 搜索：题目、答案关键词、知识点；
- 科目；
- S / A / B；
- 院校；
- 来源证据类型；
- 未练 / 已练 / 今日练过 / 到期；
- 红 / 黄 / 绿 / 熟练；
- 收藏；
- 只看跨校高频；
- 只看目标院校。

列表卡片至少显示：题目、科目、级别、来源标签、院校标签、掌握状态、是否到期。

筛选状态尽量写入 URL query / hash，允许刷新和分享后保持。

### 7.3 单题训练页

这是产品最重要的页面。

#### 默认状态

打开只显示：

- 题目；
- 科目 / S-A-B / 来源 / 院校；
- “开始作答”按钮；
- 45 / 60 / 90 秒计时器选择；
- 上一题 / 下一题 / 返回队列。

**默认绝不能直接展示答案。**

#### 作答后展开

依次展示：

1. 口述版答案；
2. 知识点解析；
3. 记忆钩子（若有）；
4. 追问；
5. 来源 / 证据说明。

#### 自评

训练结束必须选择：

- 🔴 不会；
- 🟡 知道但说乱；
- 🟢 能完整回答；
- ◆ 熟练，能接追问。

同时记录：

- 是否完成首答；
- 是否展开追问；
- 是否接住追问；
- 练习时间；
- 本题累计次数。

### 7.4 追问链

题目有 `followUps` 时：

- 首答后一次只显示一个追问；
- 用户点击“下一追问”再显示下一条；
- 不要一开始全部铺开；
- 追问可单独标记“接住 / 卡住”；
- 卡住时允许回到解析再继续。

后续可支持 `relatedQuestionIds`，但首版数据为空也不能报错。

### 7.5 间隔复习

首版采用简单透明的规则，不实现复杂 SM-2：

- 红：1 天后；
- 黄：3 天后；
- 绿：7 天后；
- 连续两次绿 / 熟练：14 天后；
- 熟练后仍可手动“提前再练”。

前端应在每次自评后计算并持久化 `nextReviewAt`。

### 7.6 复习簿 / 错题本

自动收集：

- 红题；
- 黄题；
- 追问卡住的题；
- 到期未复习；
- 用户收藏。

提供“一键开始复习本页”并形成连续队列。

### 7.7 院校模式

院校页展示 12 所学校卡片：

- 学校 / 学院；
- 报考方向；
- 当前可核验考情判断；
- 优先准备方向；
- 证据说明；
- S / A / B 题数量；
- 已练 / 掌握覆盖率。

进入院校后：

- 查看该校全部题；
- 按来源筛选；
- 一键“只练该校”；
- 将该校设为当前模式；
- Dashboard 推荐队列提高该校权重。

证据类型视觉上必须明确区分：

- 截图真题；
- 同校面经；
- 官方范围 / 官方方向 / 官方当前；
- 高概率预测；
- 官方风格参考。

### 7.8 模拟面试

用户可选择：

- 时长：10 / 15 / 20 分钟；
- 题数：5 / 10 / 15 / 20；
- 全科 / 指定科目 / 指定院校；
- S only / S+A；
- 是否包含项目追问。

模拟中：

- 全屏 / 专注模式；
- 不显示答案；
- 每题计时；
- 可以随机插入追问；
- 不允许返回修改上一题评分，模拟结束后再统一复盘。

模拟结束报告：

- 总题数；
- 红 / 黄 / 绿 / 熟练；
- 追问接住率；
- 科目薄弱分布；
- 院校覆盖；
- 本次需回炉题目列表。

### 7.9 数据与备份

数据完全浏览器本地化：

- 默认题库从 `public/data/default-dataset.json` 加载；
- 用户训练历史、设置、收藏、熟练度保存在 localStorage；
- 题库本体和用户状态尽量分离，避免默认题库升级覆盖训练历史；
- 支持完整导出 JSON 备份；
- 支持导入恢复；
- 支持“只重置默认题库，保留训练历史”；
- 支持“清空训练历史”；
- 数据结构必须带 `schemaVersion`，未来支持迁移。

### 7.10 统计

至少包含：

- 今日 / 7 日 / 30 日练习量；
- 连续练习天数；
- S 级覆盖率；
- 各科目掌握率；
- 各院校覆盖率；
- 红黄绿分布；
- 到期积压数；
- 最近练习记录。

避免做成“管理后台大屏”，统计只服务下一步行动。

## 8. P1 功能（在 P0 全部稳定后再实现）

- 题目编辑 / 新增；
- JSON 增量导入；
- `relatedQuestionIds` 相关题；
- 手动备注“我卡在哪里”；
- 本地语音录音（若实现，必须不上传服务器且允许关闭）；
- 题目随机洗牌策略；
- 模拟面试历史比较；
- 用户自定义院校训练包。

## 9. 训练状态定义

### 9.1 Mastery

- `0`：未练
- `1`：红｜不会
- `2`：黄｜知道但说乱
- `3`：绿｜能完整回答
- `4`：熟练｜能接追问

### 9.2 正式练习判定

只有完成以下步骤才写入 PracticeRecord：

1. 进入题目；
2. 开始作答或显式进入作答状态；
3. 查看答案 / 完成追问阶段；
4. 提交自评。

单纯浏览题目、搜索、收藏不算练习。

## 10. 质量要求

### 10.1 响应式

必须优先支持：

- iPhone / Android 竖屏；
- 13~16 英寸笔记本；
- 大屏桌面。

手机上单题训练必须可以单手操作，不出现横向溢出。

### 10.2 可访问性

- 键盘完整可用；
- 可见 focus；
- 正确 heading 语义；
- 图标按钮必须有 accessible name；
- 色彩不能作为唯一状态编码；
- 对比度满足 WCAG AA；
- 动画尊重 `prefers-reduced-motion`。

### 10.3 性能

246 道题首版不需要后端分页，但筛选和搜索应即时；避免无意义大依赖。

### 10.4 数据真实性

- 不得修改 `default-dataset.json` 中问题和答案的事实口径，除非明确修复结构错误；
- 真题与预测必须始终保留证据标签；
- 未知来源不得升级为“真题”；
- UI 文案不能暗示预测题是官方考题。

## 11. 视觉目标

产品不是通用 SaaS Dashboard，而是一张“现代化的个人研习桌”。

关键词：

**青云 / 问道 / 书卷 / 索引卡 / 克制 / 学术 / 现代 / 专注。**

避免：

- 蓝紫渐变 AI 风；
- 过多玻璃拟态；
- 四处漂浮的 rounded cards；
- 巨大 KPI 面板；
- 过度 emoji；
- 千篇一律 Inter + shadcn 默认视觉。

具体视觉方案见 `docs/DESIGN.md`。

## 12. 测试与验收

### 12.1 单元测试

至少覆盖：

- 数据校验；
- review due date 计算；
- 推荐队列排序；
- filter/search；
- 训练记录写入；
- 数据迁移 / import-export。

### 12.2 E2E

Playwright 至少覆盖：

1. 首次打开加载默认题库；
2. Dashboard 开始一题并完成红黄绿自评；
3. 复习时间被正确更新；
4. 题库组合筛选；
5. 指定复旦，能看到截图真题；
6. 学校模式切换；
7. 模拟面试完整走通；
8. 导出 / 导入备份；
9. 手机 viewport 无横向溢出；
10. GitHub Pages production build 基路径正确。

只有全部满足才算完成：

- `npm run lint` 通过；
- `npm run test` 通过；
- `npm run test:e2e` 通过；
- `npm run build` 通过；
- Playwright 桌面和手机视觉巡检通过；
- `frontend-design` 已用于设计 / 实现阶段；
- `web-design-guidelines` 已执行最终 UI / UX / Accessibility 审查，问题已修复；
- GitHub Pages workflow 成功；
- `https://lipume.github.io/qingyun-viva/` 可访问；
- 从线上页面截取真实产品截图并放入 `docs/screenshots/`；
- README 已升级为产品级介绍，并引用真实截图；
- git working tree clean；
- 所有完成内容提交并 push 到 `origin/main`。
